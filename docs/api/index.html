Dead or Alive — API v1

Static, read-only JSON — no key, refreshed weekly. ← back to results

Editions

  • en — English (crypto: BTCUSD, ETHUSD, 1d/4h) (methodology)
  • ko — 한국어 (Korean, crypto: KRW-BTC, KRW-ETH, 1d/4h) (methodology)
  • stocks — Stocks (SPY, QQQ, 1d) (methodology)

Endpoints (per edition)

  • GET /api/v1/<edition>/latest.json — the most recent run's full payload (identical in shape to this repo's own results/latest.json / results/latest_ko.json / results/latest_stocks.json).
  • GET /api/v1/<edition>/history/index.json — a list of every available snapshot, newest first: {"edition": "...", "history": [{"as_of": "...", "file": "history/<as_of>.json"}, ...]}.
  • GET /api/v1/<edition>/history/<as_of>.json — a copy of that edition's payload as of that date.

Row schema

payload["popular_combos"] (added by the popular-combos extension) is a second array in the same row shape as payload["rows"], for a separately pre-registered group of multi-indicator combinations — kept separate so rows keeps meaning exactly what it always meant.

Every element of payload["rows"] (and payload["popular_combos"]) carries:

  • strategy_id: registry id, e.g. "sma_cross" — see the methodology page's strategy table for the full list, including the POPULAR_COMBOS group
  • strategy_name: human-readable name of the strategy
  • params: the fixed parameter string for this variant, e.g. "10-50"; "-" for reference rows
  • type: "state" | "onebar" | "holdN" | "reference" — which engine primitive ran this row
  • asset: e.g. "BTCUSD", "KRW-BTC", "SPY"
  • timeframe: "1d" or "4h"
  • edition: "en" | "ko" | "stocks"
  • as_of: date (UTC) of the last fully-closed bar this run used, ISO YYYY-MM-DD
  • verdict: "ALIVE" | "FADING" | "DEAD" | "TOO FEW TRADES" | null (reference rows)
  • is: object of in-sample metrics — see the methodology page's metric definitions
  • oos: object of out-of-sample metrics (the ones the verdict is based on), plus fee_drag
  • robustness: object — {grid: [...], share_pf_ge_1, note}; diagnostic only, added by the parameter-neighbourhood robustness map (see methodology: "Robustness map (diagnostic)"); present on tradeable (non-reference) rows once that extension has run, absent on older history snapshots and on reference rows
  • suspicious: bool — OOS PF or Sharpe crossed the "investigate, don't trust" threshold

Cost model and verdict-badge thresholds are defined once, by reference, on each edition's methodology page linked above — not repeated as numbers here, so this page never goes stale relative to config.py.

Update cadence

Weekly, Monday 00:30 UTC. payload["generated_at"] is the run's own wall-clock time; as_of is the date of the last fully-closed price bar that run used.

Stability

Fields are only ever added, never renamed or removed. robustness is one such field, added by a later extension — its absence on an older history snapshot is not an error.

Example

import requests

data = requests.get("https://getjogak-sketch.github.io/deadoralive/api/v1/en/latest.json").json()
for row in data["rows"]:
    print(row["strategy_id"], row["params"], row["asset"], row["timeframe"], row["verdict"])
